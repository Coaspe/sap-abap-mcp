# 클라우드 Codex에 ZIP과 함께 전달할 검증 프롬프트

아래 블록을 ZIP과 함께 전달한다. 기존 SAP 연결을 재사용한다.
Claude Code와의 비교는 이번 실험에 섞지 않는다.

```text
현재 클라우드 Windows에서 Codex와 npm 배포본 SAP ABAP MCP는 이미 SAP에
연결되어 있다. 첨부 ZIP은 다른 Mac에서 수정한 미배포 코드다.
배포본 A와 수정본 B를 실제 SAP에서 비교하여, 읽기 정확성을 유지하면서
MCP 페이로드와 Codex 보고 토큰 사용량이 줄어드는지 검증해줘.
연결 재설정이나 온보딩부터 반복하지 말고 다음 절차를 실제로 실행해.

1. 실행 대상과 조건을 고정해.

ZIP 파일명:
sap-abap-mcp-local-20261006-f3184ab60549.zip
SHA-256:
d15002f612d270e754fb9b782288034843d1130bbd9c98728a65a51ff2aa1824

ZIP 해시와 LOCAL-PREVIEW.json의 파일 해시를 확인하고 새 검증 폴더에 풀어.
프로필이나 자격 증명을 복사하지 말고, 같은 Windows 사용자와 기존 SAP
프로필 경로·환경 변수·역할·정책을 재사용해. A의 실제 실행 파일과 설치된
패키지 버전·integrity를 기록하고 고정해. 실행 도중 @latest를 재해석하지 마.
A와 B 모두 1.7.1이라고 표시될 수 있으니 버전 문자열로 구별하지 마.
B의 dist/src/index.js를 실행하고, 기존 등록을 B라고 잘못 세지 마.

새 폴더 안에서 npm.cmd ci --ignore-scripts를 실행해. 이는 측정에 필요한
잠긴 개발 의존성도 설치한다. 다시 빌드하거나 npm update/audit fix를 하지 마.
node scripts/smoke-v1-stdio.mjs로 Windows 시작 검사를 수행해.
B의 기본 serve는 minimal 5개 도구가 기대값이다. 현재 등록에 명시된
--preset/--toolsets와 실측 tools/list를 기록해. preset만 다른 비교라면
버전 변경 효과와 preset 변경 효과를 구분해서 보고해.

검증 스크립트와 결과는 새 로컬 검증 폴더에서만 작성해도 된다. 제품 소스,
ZIP, 기존 설치와 영구 MCP 설정은 수정하지 마. Codex의 모델·reasoning 설정,
호스트 버전·도구 검색 방식·권한을 A/B에서 같게 유지하고, 한 평가 세션에는
테스트 대상 SAP MCP 하나만 활성화해. 다른 도구 조건도 같게 맞춰.
CLI 옵션은 설치된 codex --help와 codex exec --help에서 확인해.
임시 실행별 설정으로 대상을 바꾸고 설정·보안 규칙을 우회하지 마.
현재 대화의 MCP 도구가 실행 경로 변경만으로 교체된다고 가정하지 마.

2. 실제 SAP 읽기의 정답 기준을 먼저 고정해.

기존에 선택되어 사용 중인 SAP 대상만 사용해. 대상이 여러 개여서 현재
사용 대상을 판별할 수 없을 때만 질문해. 접근 가능한 SAP 표준 클래스의
짧은 메서드 하나와 직접 관련된 공개 타입 최대 3개를 선택해. 회사 업무
코드나 업무 데이터는 시험 대상으로 선택하지 마.

기존 ADT/Eclipse 또는 인증을 재사용하는 직접 ADT 읽기로 메서드 소스,
입출력·예외 선언, 관련 타입과 소스 위치를 확보해 정답 기준을 만들고
동일 구간의 해시를 고정해. 기준을 MCP의 자기 보고만으로 만들지 마.
이 기준의 본문과 정답은 평가 모델의 프롬프트에 넣지 마.
독립 기준을 확보하지 못하면 정확성은 UNVERIFIED로 남겨.

실제 SDK stdio 요청으로 A/B의 initialize와 tools/list를 확보해.
각 버전에서 동일 객체·동일 범위의 소스와 공개 타입을 읽고 정답 기준과
내용·범위·해시를 대조해. 선택한 메서드가 잘린 결과라면 허용 범위에서
추가로 읽거나 partial로 기록해. 잘린 응답을 완전한 결과로 세지 마.
같은 소스 범위를 즉시 다시 읽어 변경 여부를 확인해. B가 조건부 조회를
지원하면 첫 응답의 검증자를 사용하고, notModified=true일 때 해시가
일치하고 소스 본문이 생략되는지 확인해. A가 지원하지 않으면 일반 재조회로
같은 사실을 확인하고 conditional_read=unsupported로 구분해.
시험 중 소스가 바뀌면 그 비교쌍을 invalidated로 보존하고 결과를 섞지 마.

전체 카탈로그나 소스를 모델에게 무작정 덤프하지 마. 직접 노출된 도구는
바로 호출하고, B의 deferred 도구는 필요한 이름만 describe한 뒤 반환된
schemaHash와 입력 스키마로 invoke_read해. 결과는 실제 envelope에 맞춰
파싱해. B의 정상 데이터 경로는 structuredContent.data다.

scripts/live-read-context.mjs는 참고·보조용이다. 이 스크립트는 adaptive
모드로 시작하고 modelCalls=0이며, 초기 스키마·모델 사용량을 측정하지 않는다.
이 스크립트 성공을 기본 minimal 모드의 모델 평가나 토큰 절감 증거로 쓰지 마.

3. MCP 페이로드를 따로 측정해.

가능하면 측정용 harness를 만들어 실제 전송 경계에서 JSON을 메모리 안에서
계수하고 원문 대신 크기·해시·상태만 저장해. 두 버전에서 같은 tokenizer를
사용해. ZIP의 고정된 js-tiktoken과 o200k_base를 쓰면 추정치라고 명시해.

초기 tools/list의 minified tools 배열과 서버 instructions를 따로 측정해.
작업 중 모든 MCP 요청·응답을 재시도와 오류까지 포함해 측정하고, discovery,
describe, 실제 실행, Resource 읽기·prompt 조회를 구분해. 초기 스키마는
프로토콜 페이로드 합계에서 한 번만 계산해. 실제 클라이언트가 모델에게
전달한 형식이나 반복 횟수는 확인 없이 이 합계로 대체하지 마.
JSON-RPC framing 포함 여부와 계수 범위를 A/B에서 일치시켜 기록해.
MCP 호출 수, 응답 bytes, JSON token 추정치와 시간을 기록해.
추가 계측 없는 SAP 내부 HTTP 요청 수는 null로 남겨.
스크립트가 고른 호출 경로는 모델이 스스로 고른 호출 경로와 구분해.

4. 같은 작업을 독립 Codex 실행에서 비교해.

아래 평가 프롬프트의 대상 값만 고정하여 A/B에 동일하게 전달해:
"지정된 SAP 시스템의 표준 클래스 [클래스] 메서드 [메서드]를 SAP MCP로
읽고 설명해줘. 실제 동작, 입력·출력·예외, 직접 관련된 공개 타입 최대 3개를
소스 URI와 행 근거로 설명하고, 같은 소스를 한 번 다시 읽어 변경 여부를
확인해. 설명은 표 하나와 문장 5개 이내로 작성해. 확보하지 못한 근거는
미확인으로 표시해. SAP 변경이나 프로그램·테스트 실행은 하지 마."

이 긴 검증 계획과 정답 기준을 평가 프롬프트에 추가하지 마. 평가 모델은
SAP 사실을 MCP로 확보해야 한다. 로컬에 저장된 정답이나 검증 로그를 읽어
답한 실행은 무효다. MCP 프로세스 캐시는 각 실행에서 새로 시작해.

설치된 CLI가 지원하면 codex exec --json의 독립 실행과 실행별 임시 MCP
설정을 사용해. resume로 이전 대화를 잇지 마. 기존 Codex 로그인만 재사용하고
auth.json·토큰을 복사하거나 출력하지 마. 가능한 경우 --ephemeral로
원문 세션 저장을 줄이고, JSONL은 스트리밍 처리하여 필요한 사용량·호출
지표와 비민감 결과만 보존해. 사용 가능한 옵션을 추측하지 마.

첫 A/B 한 쌍부터 실행해. 모델이 실제 지정된 서버를 사용했는지 확인하고
정답 기준으로 채점해. 설정·프로토콜 문제로 평가가 성립하지 않으면 원인과
재현 정보를 기록하고 멈춰. 정상일 때만 총 3회씩, 최대 6개 독립 실행을
진행해. 실행 순서는 A-B, B-A, A-B로 번갈아 배치해. 각 실행은 최대 20개
MCP 요청, 최대 10분으로 제한하고 실패·시간 초과도 분모에 포함해.

turn.completed.usage의 input_tokens, cached_input_tokens, output_tokens와
제공되는 reasoning 사용량을 수집해. cached_input_tokens를 input_tokens에
더하지 마. 누락된 항목은 null로 기록하고 원인을 써. 제공자 캐시가 초기화됐다고
가정하지 말고 각 실행의 캐시 사용량을 같이 보고해.
Codex 보고 토큰을 청구 금액으로 표현하지 마. 해당 CLI에서 실제 모델 사용량을
확보하지 못하면 TOKEN_USAGE_UNVERIFIED로 남기고 MCP 추정치를 대체하지 마.
독립 실행이 불가능하면 프로토콜 검사만 완료했다고 보고해.

5. 증거와 판정을 남겨.

report.ko.md, measurements.json, 실행 환경 manifest, 최소 재현 스크립트를
새 검증 폴더에 저장해. 측정 중에는 코드·자격 증명·토큰·쿠키·주소·계정·
전체 config·명령줄·환경 변수를 원문 로그에 남기지 마. 최종 공유 보고서는
대상 시스템을 별칭으로 표시하고 민감 원문을 제외해. 공개 업로드는 하지 마.

결과 표에는 A/B별 정답 통과 수, 실패·부분 성공·지원 불가 수, 직접 도구 수,
초기 schema/instructions 추정치, 작업 MCP 호출·요청/응답 추정치,
Codex input/cache/output 사용량, 시간의 중앙값과 범위를 담아.
실패한 실행을 지워 좋은 결과만 보고하지 마. 두 버전 모두 정답 기준을
통과한 같은 작업에서만 절감률을 계산해. 0 또는 누락된 기준값에는 비율을
만들지 말고, 실패/invalidated 실행은 개수·비용·이유를 별도로 유지해.

최종 판정은 기능 정확성, MCP 페이로드 감소, Codex 보고 사용량 감소를
각각 PASS / FAIL / UNVERIFIED로 분리해. 프로토콜/fixture 성공을 실제
모델의 성공으로 옮겨 적지 마. 이 메서드 읽기 실험을 전체 MCP 기능, 새 사용자
온보딩, 보안 감사 통과, 표준 적합성 또는 세계 최고 성능의 증명으로 확대하지 마.
미해결 audit와 conformance 상태는 LOCAL-PREVIEW.json에 있는 그대로 보고해.

SAP 소스 수정·생성·삭제, activation, ABAP Unit·ATC·프로그램 실행,
transport 변경·release, 권한·방화벽·인증서 설정 변경은 이 요청의 범위 밖이다.
테스트 과정에서 수정본의 결함을 발견하면 제품을 고쳐 A/B 대상을 바꾸지 말고,
오류 코드·실패 조건·최소 재현만 정리해. 실제 측정한 범위만 결론 내줘.
```

Codex의 독립 실행, JSONL 이벤트, `turn.completed.usage`와 기존 로그인
재사용은 [공식 OpenAI 문서](https://learn.chatgpt.com/docs/non-interactive-mode)에
근거한다. 설치된 클라우드 CLI의 지원 여부는 현장에서 확인해야 한다.
