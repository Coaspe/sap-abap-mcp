# 2026-10-21 보고된 8개 문제 수정

이 문서는 2.2.0 수정본의 동작과 검증 범위를 기록합니다.
보고된 B4D 재현 결과를 수정 근거로 삼았으며, 이번 작업에서 실제 SAP 쓰기·활성화·릴리스는 실행하지 않았습니다.
수정은 2.2.0에 포함됩니다. 이전 npm 2.1.0 패키지는 변경되지 않습니다. 로컬 테스트 통과가 실제 B4D 수정 성공을 증명하지는 않습니다.

| 보고된 문제 | 수정된 동작 | 검증 |
|---|---|---|
| `sap.source.patch`에서 `$` 손상 | 정확히 찾은 위치 전후를 잘라 연결합니다. CRLF 경로도 치환 문자열 패턴을 해석하지 않습니다. | `$$`, `$&`, 달러+백틱, 달러+작은따옴표, `$1`이 그대로 남는지 확인 |
| 객체가 있는 Transport 릴리스 500 | 객체가 있는 Task/Request는 처음부터 `application/http` 요청을 ADT background-run 자원에 제출합니다. 상태를 폴링하고 결과 HTTP 응답을 해석합니다. | Task→Request 순서, 단일 제출, 실패·타임아웃·잘못된 URI, 결과 HTTP 오류 확인 |

| DOMA/DTEL의 잘못된 ABAP 문법 검사 | Dictionary 객체를 text/plain ABAP 검사에 보내지 않습니다. 지원되는 Dictionary reporter로 inactive 객체를 검사합니다. 별도 reporter가 없으면 경고를 반환하고 명시적으로 요청한 activation의 SAP 검증을 사용합니다. 실제 Dictionary 오류는 계속 activation을 막습니다. | DOMA/DTEL artifact 없는 검사, unavailable 경고, 실제 E 차단, unlock 후 activation 확인 |

## 비동기 프로토콜 확인 근거

공개된 [SAP Eclipse 업데이트 저장소](https://tools.hana.ondemand.com/latest/)의 SAP 배포 모듈을 읽어
요청 형식과 상태·응답 처리 흐름을 확인했습니다. 모듈 자체를 프로젝트에 복사하거나 실행하지 않았습니다.

- `com.sap.adt.communication_3.62.0.jar`: SHA-256 `905b13f510902a1b234665eefa9a1fe85b36e8f83289038130f26e7c9ac4649b`.
  `BackgroundRestResource`, `ApplicationHttpRequestContentHandler`, `ApplicationHttpResponseContentHandler`, `BackgroundRunContentHandler`의 프로토콜 상수와 호출 흐름을 확인했습니다.
- Background submission은 `application/http`, polling은 `application/vnd.sap.adt.bgrun.v1+xml`, 결과는 `application/http`입니다.
  `new/running/finished/failed/processNotStarted` 상태와 `http://www.sap.com/adt/relations/runs/result` 링크를 처리합니다.
  기본 폴링 간격은 10초, 전체 대기 한도는 120초입니다. 타임아웃은 성공이 아닙니다.
- `com.sap.adt.transport_3.62.0.jar`: SHA-256 `63ee3181cdc4fe46df0621d83285e978da8059f5d91e19237bef62acb9556dd9`.
  `TransportSearchService`와 `TransportSearchConfiguration`에서 검색 template 관계, `requestWithTask`, 날짜 범위와 상태 필터를 확인했습니다.

모든 URL은 같은 SAP origin과 ADT 경로 안에서만 사용합니다. background-run의 polling/result 링크는
해당 background-run 경로 밖을 허용하지 않습니다. 실패 후 변경 요청을 자동으로 재전송하지 않습니다.

## 남아 있는 검증 범위

오래된 Transport 검색은 discovery가 그 기능과 날짜 범위를 광고하는 시스템에서 작동합니다.
추가 상세 조회가 200건을 넘거나 조회가 실패하면 `historyComplete: false`와 이유를 반환합니다.
사용자 목록은 다른 모든 사용자의 모든 잠금에 대한 완전한 증거가 아닙니다.

실제 B4D에서 객체가 있는 Transport 릴리스, RAP 생성/서비스 unpublish, Dictionary activation과
최상위 패키지 생성이 성공했는지는 아직 확인하지 않았습니다. 이 단계는 이번 로컬 코드 수정과 구분합니다.

수정본은 `npx -y @coaspe/sap-abap-mcp@2.2.0 onboard`로 시작합니다.
기존 호스트 등록이 2.1.0을 고정하고 있다면 doctor/repair로 2.2.0 실행 경로를 검토해 적용하고 호스트를 다시 시작해야 합니다.
